# 30denní validační a prodejní playbook

## Cíl

Do 30 dnů získat tři placené piloty v jediném segmentu a zjistit:

1. kolik relevantních hovorů firmám skutečně propadá,
2. zda automatizace zvládá českou konverzaci bez nebezpečných chyb,
3. zda klient po pilotu zaplatí pravidelný paušál.

## Týden 1: problém, ne produkt

- Vyberte jeden segment, například pneuservisy v jednom kraji.
- Sestavte seznam 50 firem z veřejných firemních katalogů; neautomatizujte nevyžádané hromadné oslovování.
- Udělejte 15 krátkých rozhovorů s majitelem nebo člověkem, který bere telefony.
- Získejte anonymizované příklady nejčastějších dotazů a zmeškaných situací.
- Nechte si ukázat současný kalendář a postup předání zakázky.

### Otázky bez podsouvání řešení

1. „Co se stane, když během práce nezvednete telefon?“
2. „Kolik hovorů typicky zmeškáte v rušném dni a kolika lidem voláte zpět?“
3. „Jak poznáte, že šlo o hodnotnou zakázku?“
4. „Které informace potřebujete znát, než nabídnete termín?“
5. „Kterou otázku volající pokládají pořád dokola?“
6. „Co se nesmí nikdy slíbit bez vašeho potvrzení?“
7. „Kolik by pro vás měla cenu jedna dodatečná skutečně realizovaná zakázka?“
8. „Ukažte mi poslední konkrétní případ, ne odhad.“

Za silný signál považujte konkrétní minulý příklad, data z telefonu/CRM a ochotu zaplatit zálohu. Zdvořilé „to zní zajímavě“ není validace.

## Týden 2: concierge prototyp

- Připravte pouze pět nejčastějších scénářů.
- Začněte přesměrováním při nezvednutí nebo mimo pracovní dobu.
- Nechte člověka schvalovat rezervace a nestandardní odpovědi.
- Proveďte alespoň 100 testů: hluk, nářečí, přerušování, změna názoru, nesrozumitelná adresa, cizinec, žádost o člověka a nouzová situace.
- Zapište očekávaný a skutečný výsledek každého testu.

### Minimální akceptační test

Pilot se nesmí pustit, pokud systém:

- zatajuje, že je automatizovaný,
- neumí okamžitě předat nebo ukončit hovor,
- vymýšlí ceny, dostupnost či odborné rady,
- ukládá více osobních údajů, než je pro domluvený účel nutné,
- nemá funkční postup při výpadku.

## Týden 3: tři placené piloty

Nabídněte pevný rozsah, datum konce a cenu. I symbolicky placený pilot je silnější signál než bezplatný test.

### Krátký úvod pro telefon/e-mail

> Pomáhám [konkrétní segment] zachytit poptávky, když nikdo nemůže zvednout telefon. Asistent česky zjistí důvod volání, kontakt a preferovaný termín; nic závazného neslíbí a složitý případ předá člověku. Hledám tři firmy pro 14denní měřený pilot. Nejdřív bych chtěl pochopit, co se u vás dnes děje se zmeškanými hovory. Má smysl 15 minut nad konkrétními čísly?

### Nabídka pilotu na jednu stránku

- výchozí stav za poslední dva týdny,
- přesný rozsah a zakázané scénáře,
- metrika úspěchu dohodnutá s klientem,
- cena, minutový limit a cena nad limit,
- práce s daty a doba uchování,
- kdo a do kdy řeší eskalaci,
- co se stane při výpadku,
- datum rozhodnutí o placeném pokračování.

Pro každého klienta vytvořte jednoduchý report:

| zmeškané příchozí hovory |  |  |  |
| zachycené kontakty | 0 |  |  |
| kvalifikované poptávky | 0 |  | potvrzené klientem |
| rezervace | 0 |  |  |
| skutečně uskutečněné zakázky | 0 |  |  |
| předání člověku | — |  | důvody |
| faktické/procesní chyby | — |  | závažnost |

Položte závěrečnou otázku: **„Budete od příštího měsíce pokračovat za X Kč bez DPH?“** Pokud ne, zjistěte konkrétní důvod a nic dalšího neautomatizujte, dokud se stejný problém neopakuje u více klientů.

## Rozhodovací pravidla

### Pokračovat

- alespoň dva ze tří pilotů přejdou na pravidelnou platbu,
- žádná závažná chyba nebo bezpečnostní událost,
- klienti potvrzují konkrétní získané příležitosti,
- podpora a variabilní náklady ponechávají rozumný prostor v ceně,
- většina scénářů je mezi klienty stejná.

### Upravit

- poptávka existuje, ale hlas je slabý → SMS/webový follow-up po zmeškaném hovoru,
- hodně předání člověku → užší rozsah a lepší kvalifikace,
- výsledek je dobrý, ale marže slabá → minutové limity, vyšší cena, méně integrací.

### Zastavit

- firmy nemají měřitelný objem zmeškaných hodnotných hovorů,
- nikdo nechce po pilotu platit,
- každý klient vyžaduje zcela unikátní proces,
- riziko chyb je vzhledem k hodnotě služby nepřijatelné.
